# MkDocs + GitHub 博客项目结构与日常更新流程

(因为总是记不住,让AI总结了一篇教程)

这篇文章记录本博客项目的目录结构，以及以后**写文章、修改文章、上传 GitHub、更新网站**的最简单操作流程。

目标很简单：

> **想写文章 → 放到正确目录 → 本地检查 → Git 提交 → Push → 等待网站自动更新。**

------

## 一、项目结构

博客项目目录：

```text
homelab-blog/
├── docs/                    # 博客正文
│   ├── index.md             # 首页
│   ├── assets/              # 图片、图标等资源
│   ├── diary/               # 日记 / 随笔
│   ├── network/             # 网络相关
│   ├── projects/            # 项目记录
│   ├── references/          # 参考资料
│   └── servers/              # 服务器相关
│       ├── luna/
│       └── lianpo/
│
├── mkdocs.yml               # MkDocs 配置文件
└── ...
```

### 最重要的几个位置

| 文件 / 目录     | 用途                   |
| --------------- | ---------------------- |
| `docs/`         | 所有博客正文           |
| `docs/assets/`  | 图片等资源             |
| `docs/servers/` | 服务器相关博客         |
| `mkdocs.yml`    | 整个博客的 MkDocs 配置 |
| `docs/index.md` | 博客首页               |

**以后写文章，主要就是操作 `docs/`。**

------

# 二、写一篇新文章

例如我要写一篇 LianoPo 服务器的文章。

先进入项目：

```bash
cd ~/homelab-blog
```

进入对应目录：

```bash
cd docs/servers/lianpo/
```

创建文章：

```bash
vim 新文章.md
```

例如：

```bash
vim IPv6配置记录.md
```

写完保存即可。

------

# 三、修改已有文章

直接编辑对应的 Markdown 文件：

```bash
vim docs/servers/lianpo/IPv6配置记录.md
```

或者使用自己喜欢的编辑器。

修改完成后，不需要做其他特殊操作。

------

# 四、图片放哪里？

博客中的图片统一放到：

```text
docs/assets/
```

例如：

```text
docs/
├── assets/
│   ├── lianpo-ipv6.png
│   └── network-topology.png
└── servers/
    └── lianpo/
        └── IPv6配置记录.md
```

Markdown 中引用：

```markdown
![IPv6网络结构](../../assets/lianpo-ipv6.png)
```

具体相对路径根据 Markdown 文件所在目录调整。

# 五、写完后先看 Git 有没有发现修改

回到项目根目录：

```bash
cd ~/homelab-blog
```

执行：

```bash
git status
```

例如：

```text
modified:   docs/servers/lianpo/IPv6配置记录.md
```

或者：

```text
new file:   docs/servers/lianpo/IPv6配置记录.md
```

说明 Git 已经发现修改。

# 六、上传博客的标准流程

以后最重要的就是记住下面这 **4 步**：

```bash
git pull --ff-only
git add .
git commit -m "提交说明"
git push
```

### 第 1 步：先同步 GitHub

```bash
git pull --ff-only
```

作用：

> **先把 GitHub 最新内容同步到本地。**

养成习惯：

**写博客之前先 pull。**

------

### 第 2 步：添加修改

```bash
git add .
```

作用：

> 把这次新增、修改、删除的文件交给 Git 准备提交。

这里的 `.` 表示：

> 当前项目目录下的所有修改。

------

### 第 3 步：创建 commit

```bash
git commit -m "新增LianoPo服务器记录"
```

其中：

```text
-m
```

表示后面的文字是**提交说明**。

例如：

```bash
git commit -m "新增LianoPo服务器记录"
git commit -m "修改网络配置文章"
git commit -m "增加服务器截图"
```

------

### 第 4 步：上传 GitHub

```bash
git push
```

看到类似：

```text
main -> main
```

一般就说明上传成功。

------

# 七、以后最简单的记忆方法

把整个流程记成：

```text
先拿 → 再放 → 记录 → 上传
```

对应：

```bash
git pull --ff-only    # 先拿：拿 GitHub 最新内容

git add .             # 再放：把自己的修改交给 Git

git commit -m "xxx"   # 记录：给这次修改做一个记录

git push              # 上传：推送到 GitHub
```

也就是：

> **Pull → Add → Commit → Push**

# 十、如果移动文章

推荐使用：

```bash
git mv 原位置 新位置
```

例如：

```bash
git mv docs/servers/luna/搭建mkdocs+github博客.md \
       docs/servers/lianpo/
```

然后正常：

```bash
git add .
git commit -m "调整博客目录"
git push
```

如果已经使用普通 Linux 命令：

```bash
mv 原位置 新位置
```

也没关系。

Git 会自动检测文件移动/重命名。

之后：

```bash
git status
git add .
git commit -m "调整博客目录"
git push
```

即可。

# 十一、`git status` 看不懂怎么办？

永远可以先执行：

```bash
git status
```

它是最重要的检查命令之一。

例如：

```text
modified:
```

表示：

> 文件被修改了。

```text
new file:
```

表示：

> 新建了文件。

```text
deleted:
```

表示：

> 文件被删除了。

```text
renamed:
```

表示：

> 文件被移动/重命名了。

# 十二、几个容易犯的错误

## 1. `git commit` 少写 `-m`

错误：

```bash
git commit "新增文章"
```

正确：

```bash
git commit -m "新增文章"
```

------

## 2. 不要输入 `git .`

错误：

```bash
git .
```

`git` 后面必须跟具体的 Git 子命令。

例如：

```bash
git status
git add .
git commit -m "xxx"
git push
```

------

## 3. Push 被拒绝怎么办？

如果看到：

```text
rejected
fetch first
```

不要马上 `--force`。

先：

```bash
git pull --ff-only
```

如果成功，再：

```bash
git push
```

------

# 十三、GitHub 和博客网站是什么关系？

本博客的大致流程：

```text
              本地电脑
                 │
                 │ git push
                 ▼
          ┌──────────────┐
          │    GitHub    │
          │ homelab-blog │
          └──────┬───────┘
                 │
                 │ 自动构建 / 部署
                 ▼
             博客网站
```

所以平时**不需要手动去 GitHub 上传文件**。

本地：

```bash
git push
```

之后 GitHub 收到新的 commit。

如果自动部署正常，等待部署完成后，博客网站就会更新。

------

# 十四、网站没有马上更新怎么办？

先确认 GitHub 是否收到最新 commit。

然后进入 GitHub：

```text
Actions
```

查看最近一次部署任务。

### 绿色 ✅

表示部署成功。

等一会儿刷新博客即可。

### 黄色 🟡

表示还在部署。

稍等即可。

### 红色 ❌

表示部署失败。

需要查看 Actions 的错误信息。

> **先同步，再修改；修改之后 Add、Commit、Push。**
